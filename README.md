# IntegrationSolution
Solution for integrate Wialon tracking system and SAP derived files. The project is written in WPF using MahApps.Metro and Prism. There are customize a few controls for provide unusual logic.

![Иллюстрация к проекту](https://github.com/ankriukov/IntegrationSolution/blob/master/6.png)

At all there are exists 4 steps for doing analytics of data.
Start menu contains dynamic filters for excel files and their headers (from SAP). Therefore, if the files do not fit, then the next step is not possible.

# Localization

The UI is available in **English** (default), **Ukrainian** and **Russian**. The language is chosen in
**Settings → General → Interface language**; it switches immediately (no restart) and is remembered per Windows user
(user-scoped .NET settings in `%LocalAppData%`, so no write access to the installation folder is needed).

How it works:

* All UI strings live in `IntegrationSolution.Localization/Resources/Strings.resx` (English, neutral) with
  `Strings.uk.resx` / `Strings.ru.resx` compiled into satellite assemblies (`uk\`, `ru\`).
* XAML uses `xmlns:loc="clr-namespace:IntegrationSolution.Localization.Markup;assembly=IntegrationSolution.Localization"` and
  * `{loc:Loc Key}` – localized text that refreshes when the language changes;
  * `{loc:LocFormat Key, Arg0={Binding Value}, FallbackValue='-', TargetNullValue='-'}` – localized composite format
    (replacement for `Binding.StringFormat` with hard-coded words).
* C# uses the strongly typed `Strings.Key` (`IntegrationSolution.Localization.Resources`); view models that build texts in code
  refresh them in `ViewModelBase.OnLanguageChanged()` (wizard titles via `SetTitleResourceKey`), other classes can listen through
  `LanguageChangedEventManager` (weak event).
* `ILocalizationService` is registered in the Prism container (`LocalizationService.Instance`, initialized in `App.OnStartup`
  before any view is created).
* Only the UI language (`CurrentUICulture`) is switched. Number/date formatting and the parsing of SAP/Excel data keep the Windows
  regional settings, and data contracts (SAP column headers, Wialon report labels) are intentionally not translated.

Adding a string: add it to `Strings.resx` (Visual Studio regenerates `Strings.Designer.cs`) **and** to `Strings.uk.resx` and
`Strings.ru.resx`, using `Area_Name` keys. The unit tests in `IntegrationSolution.Tests/Localization.Tests` fail if a translation is
missing, placeholders differ between languages, a XAML key does not exist, or hard-coded Cyrillic text appears in XAML.

Adding a language: add `Strings.<culture>.resx`, list the language in `LocalizationService.CreateDefaultLanguages()` and include the new
satellite folder in the setup project (it already ships the "Localized resources" output of `IntegrationSolution.Localization`).
